# gentr — графовая циркуляционная замена Transformer

Архитектура с линейной сложностью O(N·k) вместо квадратичной O(N²). Внимание заменено на циркуляцию по фиксированной фрактальной топологии. KV-кэш не нужен — контекст распределён по вершинам графа.

## Проблема: две причины отказа от Transformer

### Причина 1: вес KV-кэша

В стандартном Transformer каждый токен вычисляет внимание ко всем остальным:

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

Матрица Q·Kᵀ имеет размер N × N. При инференсе на длинных последовательностях KV-кэш хранит ключи и значения для всех предыдущих токенов — O(N²) памяти. Для задачи вайбкодинга на локальной машине это означает, что контекст больше нескольких тысяч токенов просто не влезает в память.

gentr заменяет полносвязное внимание на циркуляцию по фиксированному графу. Каждый узел соединён только с соседями по топологии. Сложность: O(N·k) где k — константа (6-9 соседей).

### Причина 2: точность на структурных данных

Transformer не различает уровни вложенности. Параграф, подпункт, сноска — всё токены в плоской последовательности. Для инженерных задач (строительные нормы, юридические документы, математические доказательства) это источник галлюцинаций. Модель не имеет индуктивного смещения в сторону иерархии.

gentr кодирует структуру в топологии. Фрактальная решётка естественно создаёт иерархические уровни взаимодействия: локальные треугольники соединяют соседние токены, крупные треугольники — удалённые разделы документа.

## Теоретический фундамент

### Дискретные позиции вместо sin/cos

#### Непрерывный sin/cos (Transformer)

В оригинальном Transformer позиция токена i кодируется синусоидами:

```
P(i, 2k)   = sin( i / 10000^(2k/d) )
P(i, 2k+1) = cos( i / 10000^(2k/d) )
```

Скалярное произведение позиционных векторов зависит только от разности позиций:

```
P_i · P_j = Σ_k cos( (i − j) / θ_k ) = f(i − j)
```

Это гомоморфизм групп: i ↦ P_i переводит сложение позиций в умножение комплексных экспонент. Но это непрерывное, гладкое отображение — позиции i и i+1 всегда близки. Иерархия не кодируется.

#### Дискретный CRT (gentr)

Вместо непрерывной группы S¹ (окружности) используем конечную группу — произведение циклических групп:

```
G = Z/m₁ × Z/m₂ × … × Z/m_k
```

По Китайской теореме об остатках (CRT): если m₁, m₂, …, m_k попарно взаимно просты, то отображение

```
φ: Z/n → G,    φ(i) = ( i mod m₁, …, i mod m_k )
```

является изоморфизмом при n = m₁·m₂·…·m_k. Позиции в диапазоне [0, n−1] однозначно кодируются набором остатков.

В коде: m₁ = 2, m₂ = 3, m₃ = 5, m₄ = 7, период n = 210 — достаточно для 123 узлов при L=4.

Каждый остаток преобразуется в вектор через обучаемую таблицу E_k: Z/m_k → R^d_k:

```
P_i = Concat( E₁[i mod 2], E₂[i mod 3], E₃[i mod 5], E₄[i mod 7] )
```

Свойства CRT-позиций:

- **Дискретность.** Соседние позиции могут иметь совершенно разные коды — в отличие от sin/cos, где P_i ≈ P_(i+1).
- **Иерархичность.** Модуль 2 кодирует чётность (верхний уровень), модуль 7 — тонкую позицию. Это естественно отражает дерево документа.
- **Точная периодичность.** P_(i+n) = P_i при n = 210 — в отличие от sin/cos, где периодичность приблизительная.

#### Связь с p-адическими числами

Все возможные модули CRT образуют проективную систему: Z/m ← Z/(m·m′) — отображение взятия остатка. Обратный предел этой системы — профинитное пополнение целых чисел Ẑ. Это дискретный аналог окружности S¹ в теории характеров Понтрягина.

Если ограничиться модулями m = p^k для одного простого p, получаем p-адические числа Z_p. Расстояние в p-адической метрике:

```
d_p(i, j) = p^( −v_p(i − j) )
```

где v_p(z) — максимальная степень p, делящая i − j. В этой метрике i = 4 ближе к i = 8, чем к i = 6 (при p = 2) — потому что 4 и 8 находятся в одном блоке двоичного дерева. Это идеальная метрика для иерархических структур.

### Диффузия на графе вместо softmax-внимания

#### Уравнение теплопроводности на графе

Вместо дискретных слоёв Transformer — непрерывный по времени поток информации. Состояние вершин h(t) ∈ R^(N×d) эволюционирует согласно уравнению:

```
dh_i/dt = − Σ_{j ∈ соседи(i)} α_ij · (h_i − h_j)
```

В матричной форме:

```
dH/dt = −L_α · H
```

где L_α — взвешенный лапласиан графа: L = D − A, D — диагональная матрица степеней, A — матрица смежности с весами α_ij.

Решение: H(t) = e^(−L·t) · H(0). Вместо вычисления матричной экспоненты — итерационное решение методом Эйлера:

```
H^(k+1) = H^(k) − Δt · L·H^(k)
```

Один шаг итерации в коде — один вызов `circulation_accumulate_delta` (v2; в v1 — один цикл CW+CCW).

#### Почему диффузия, а не внимание

1. **Память.** Лапласиан L — разреженная матрица: в каждой строке k ненулевых элементов (только соседи). Умножение L·H стоит O(N·k·d) вместо O(N²·d).
2. **Структура.** Диффузия естественно уважает топологию. Близкие в графе узлы влияют друг на друга сильнее.
3. **Сходимость.** При достаточно малом Δt итерации Эйлера сходятся к равновесному состоянию, которое отражает глобальную структуру графа.

#### Роль нелинейности (ReLU)

Линейная диффузия dh/dt = −L·h имеет решение h(t) = e^(−L·t)·h(0), которое экспоненциально затухает к среднему значению. Информация теряется.

Нелинейность ReLU(W · lap) решает эту проблему двумя способами:

- W — обучаемая матрица, которая может усиливать или подавлять различные компоненты лапласиана
- ReLU обрезает отрицательные значения, создавая направленный поток: информация течёт от узлов с большими значениями к узлам с меньшими, но не обратно

Это превращает пассивную диффузию в активный транспорт информации.

### Фрактальная топология Серпинского

#### Построение

Треугольник Серпинского уровня L строится рекурсивно:

1. Базовый треугольник с вершинами 0, 1, 2
2. Для каждого треугольника уровня ℓ > 0:
   - Найти середины рёбер: ab, bc, ca
   - Рекурсивно построить три под-треугольника уровня ℓ−1:
     - Верхний: (a, ab, ca)
     - Правый: (b, bc, ab)
     - Левый: (c, ca, bc)
   - Центральный треугольник (ab, bc, ca) **не заполняется** — это «дырка» Серпинского

#### Числа

Число вершин: V(L) = (3^(L+1) + 3) / 2
Число треугольников: T(L) = (3^(L+1) − 1) / 2

| L | Вершин | Треугольников | Уровень 0 (мелких) | Уровень L (крупных) |
|---|--------|--------------|--------------------|--------------------|
| 0 | 3 | 1 | 1 | 1 |
| 1 | 6 | 4 | 3 | 1 |
| 2 | 15 | 13 | 9 | 1 |
| 3 | 42 | 40 | 27 | 1 |
| 4 | 123 | 121 | 81 | 1 |
| 5 | 366 | 364 | 243 | 1 |

#### Иерархическая циркуляция

Треугольники уровня 0 соединяют ближайших соседей — локальный контекст. Треугольник уровня L соединяет три угла всего графа — глобальный контекст.

Циркуляция идёт послойно: сначала все треугольники уровня 0, затем уровня 1, и так до L. Это позволяет информации проходить от локального к глобальному за O(log N) шагов вместо O(N) для плоской решётки.

#### Сложность

| Операция | Плоская сетка | Фрактальная |
|---|---|---|
| Число рёбер на узел | ~6 | ~6-9 |
| Число треугольников | ~2N | ~N |
| Циркуляция (1 проход по уровням) | O(N) | O(N·(L+1)) |
| Дальность связи за 1 проход | O(√N) | O(N) — верхний уровень покрывает всё |

## Архитектура v2 (single-node) — ТЕКУЩАЯ

> Актуальная реализация (ветки `single-node`, `numerical-analysis`). Соответствует
> исходной идее: три вершины треугольника — один и тот же токен в трёх ролях,
> а не три отдельных состояния.

### Одно состояние, три роли

Каждый узел хранит **один вектор** h_i ∈ R^D. Три «ипостаси» из исходной ASCII-схемы — это роли одного объекта, возникающие в разные моменты итерации:

| Роль | Что это | Где живёт |
|---|---|---|
| данность | значение h_i | состояние |
| связь | поток lap_i(h) = Σ_j (ew_ij / deg_i) · (h_j − h_i) по рёбрам | временный `delta` внутри итерации |
| выход | чтение W_o · h_i после циркуляции | readout-проекция |

Никаких отдельных буферов h_c/h_o: связь — промежуточная переменная шага, выход — проекция финального состояния.

### Шаг циркуляции (явный Эйлер, Jacobi)

```
h_i += Δt · Σ_{△ ∋ i} ReLU( W_layer · lap_i(h) ) + γ · x_i
```

где сумма берётся по всем треугольникам, содержащим узел i, а lap_i(h) — нормированный лапласиан из таблицы выше.

- `lap` считается из h **до** обновления (Jacobi) — все вклады треугольников независимы
- одна обучаемая матрица W на слой (вместо W_cw + W_ccw)
- source term γ·x_i (входной эмбеддинг) препятствует затуханию сигнала
- residual встроен в сам шаг (h += …), отдельный механизм не нужен

### Нормированный лапласиан и условие Куранта

Лапласиан нормирован на степень узла (D⁻¹L вместо L). Спектральный анализ ([test_spectral.cpp](src/test_spectral.cpp), power iteration, L=2..6):

| Оператор | λ_max | Предел Куранта Δt < 2/λ_max |
|---|---|---|
| Комбинаторный L | 6.0 | 0.333 |
| Нормированный D⁻¹L | **1.5** | **1.333** |

λ_max **инвариантен к уровню фрактала** — следствие самоподобия. Выбран Δt = 0.5: половина безопасной зоны, запас 2.7×, гарантированно устойчив на любом L и любой топологии с ограниченной степенью. Это не эмпирическая константа, а следствие условия Куранта.

### Полный цикл циркуляции v2

```
Вход:  h[i] = emb[token_i] + pos_enc[i]   для i < SEQ_LEN   (позиция на ВХОДЕ)
       h[i] = 0                            для i ≥ SEQ_LEN

Для layer = 0..NUM_LAYERS-1:
    Для lvl = 0..FRACTAL_LEVEL:
        Для iter = 0..CIRCULATION_ITERS-1:
            history[slot] = h                      [для BPTT]
            delta = Σ_△ ReLU(W[layer] · lap(h))    [Jacobi, нормировка 1/deg]
            h += Δt·delta + γ·input_emb            [Δt=0.5, γ=0.002]

Выход: output[i] = W_o · h[i]   для i < SEQ_LEN   (обучаемый readout)
```

### Обучение v2

Backward — один поток градиента через все слоты BPTT (от последнего к первому):

```
grad_h = W_o^T · grad_output            [readout backward, dW_o += grad_output ⊗ h]
Для slot = total-1 .. 0:
    grad_in = snapshot(grad_h)          [входящий градиент слота]
    grad_input += γ · grad_in           [source term backward]
    Для каждого треугольника:
        lap, proj = recompute(h_history[slot])
        gp = Δt · grad_in ⊙ ReLU'(proj)
        dW += gp ⊗ lap;  gl = W^T · gp
        grad_h[neighbors] += gl·ew/deg; grad_h[self] -= Σ(gl·ew)/deg
grad_input += grad_h                    [прямой путь входа]
```

Ключевое отличие от v1: тождественная часть residual уже содержится в grad_h (шаг h += Δt·F(h) даёт ∂h_after/∂h_pre = I + Δt·F′), поэтому отдельного сложения grad_h_v_new + grad_h_v_residual не нужно. Снимок `grad_in` обязателен: узел входит в несколько треугольников, и чтение уже модифицированного grad_h дало бы ошибку (это был реальный баг первой версии backward).

Градиенты проверены finite differences: 0.001–0.5% ([test_backward.cpp](src/test_backward.cpp)).

## Архитектура v1 (three-aspects) — историческая

> Первая реализация (ветка `master`, коммит ed1833a). Сохранена для сравнения
> A/B. В ней «три ипостаси токена» были поняты как три отдельных вектора
> состояния — дрейф от исходной идеи, исправленный в v2.

### Три ипостаси токена

Каждый узел графа (токен) имеет три представления:

- **h_v** (vertex) — состояние вершины. То, что токен «знает» о себе и контексте.
- **h_c** (connection) — связи. То, как токен относится к соседям. Вычисляется из h_v через CW.
- **h_o** (output) — выход. Комбинация: h_o = 0.5·h_v + 0.3·h_c + 0.2·pos

Разделение на h_v и h_c позволяет модели одновременно хранить и содержание токена, и его структурные отношения.

### CW: вершины → связи

Для каждого треугольника (a, b, c) с весами рёбер ew_ab, ew_bc, ew_ca:

**Лапласиан в вершине a:**

```
lap[a] = ew_ab·h_v[b] + ew_ca·h_v[c] − (ew_ab + ew_ca)·h_v[a]
```

Лапласиан измеряет, насколько вершина отличается от своих соседей. Если все три вершины одинаковы — лапласиан равен нулю. Если a отличается от b и c — лапласиан велик.

**Проекция и активация:**

```
h_c[a] += ReLU( W_cw · lap[a] )
```

Матрица W_cw ∈ R^(D×D) — обучаемая. Она выбирает, какие компоненты разницы важны. ReLU гарантирует, что связи только добавляются (нет отрицательных связей).

Аналогично для вершин b и c.

**Геометрический смысл:** CW вычисляет «напряжение» в каждом треугольнике — насколько вершины рассогласованы. Это напряжение создаёт связи h_c, которые затем служат входом для CCW.

### CCW: связи → вершины

Для каждого узла i:

```
avg = h_c[i] / n_tris(i)

h_v[i] += ReLU( W_ccw · avg )
```

Усреднение по числу инцидентных треугольников n_tris(i) нормирует вклад связей: узлы, участвующие во многих треугольниках, не должны доминировать.

**Геометрический смысл:** Связи (напряжения) «оседают» обратно в вершины, обновляя их состояние. Это замыкает цикл: вершины → связи → вершины. Одна итерация CW+CCW — один шаг распространения информации по графу.

### Полный цикл циркуляции v1

```
Вход: эмбеддинги токенов → h_v[0..SEQ_LEN-1]
       h_v[SEQ_LEN..NODES-1] = 0   (пустые узлы)

Для layer = 0..NUM_LAYERS-1:
    h_v_pre = h_v                    [сохранить для residual]
    Для lvl = 0..FRACTAL_LEVEL:
        Для iter = 0..CIRCULATION_ITERS-1:
            h_c = 0
            CW: h_c += ReLU(W_cw[layer] · lap(h_v))
            CCW: h_v += ReLU(W_ccw[layer] · avg(h_c))
            h_v += γ · input_emb      [source term]
    h_v = h_v_pre + h_v               [residual connection]

Выход: h_o = 0.5·h_v + 0.3·h_c + 0.2·pos
```

**Source term** (γ = 0.002). Чистая диффузия затухает к среднему — информация о входе теряется. Добавление малой доли исходного эмбеддинга на каждом шаге предотвращает это. Аналог residual connection в Transformer, но на уровне итераций, а не слоёв.

**Residual между слоями.** h_v(layer+1) = h_v(layer) + Circulation(h_v(layer)). Позволяет градиенту течь напрямую через слои, предотвращая проблему исчезающего градиента.

### Обучение v1

#### Forward pass

```cpp
gentr_forward(tokens, emb, mesh, buf):
    // 1. Загрузить эмбеддинги
    h_v[0..SEQ_LEN-1] = emb[tokens]
    h_v[SEQ_LEN..NODES-1] = 0

    // 2. Циркуляция по слоям
    slot = 0
    for layer in 0..NUM_LAYERS-1:
        h_v_pre = h_v
        for lvl in 0..FRACTAL_LEVEL:
            for iter in 0..CIRCULATION_ITERS-1:
                history[slot].h_v = h_v      // сохранить для BPTT
                h_c = CW(h_v, W_cw[layer])
                history[slot].h_c = h_c
                h_v += CCW(h_c, W_ccw[layer])
                h_v += γ · input_emb
                ++slot
        h_v = h_v_pre + h_v                  // residual

    // 3. Комбинировать ипостаси
    h_o = 0.5·h_v + 0.3·h_c + 0.2·pos
    output = h_o[0..SEQ_LEN-1]
```

#### Backward pass (BPTT)

Обратный проход идёт от последнего circulation-шага к первому. Для каждого шага (слота):

```
1. Source term backward:
   grad_input += γ · grad_h_v

2. CCW backward:
   Для каждого узла i:
       proj = W_ccw · avg(h_c[i])
       gp = grad_h_v[i] · ReLU'(proj)
       dW_ccw += gp ⊗ avg(h_c[i])
       grad_h_c[i] += W_ccw^T · gp / n_tris(i)

3. CW backward:
   Для каждого треугольника (a,b,c):
       Для каждой вершины:
           lap = ... (лапласиан на h_v_pre)
           proj = W_cw · lap
           gp = grad_h_c[vertex] · ReLU'(proj)
           dW_cw += gp ⊗ lap
           gl = W_cw^T · gp
           grad_h_v_new += gl · edge_weights
           d_edge_weights += gl · (h_v_pre[neighbor] - h_v_pre[self])

4. Residual backward:
   grad_h_v = grad_h_v_new + grad_h_v_residual
   grad_h_c = 0
```

Градиент по входным эмбеддингам складывается из двух источников:
- Прямой градиент от h_v (последний слой): `grad_input += grad_h_v`
- Градиент от source term на каждом шаге: `grad_input += γ · grad_h_v` (на каждом circulation-шаге)

### Почему v1 заменена на v2

«Три ипостаси» в исходной идее (ASCII-схема, plans/3.md) означали **три роли одного токена**, а не три отдельных вектора состояния. v1 реализовала их как три буфера — дрейф, который добавил параметры и произвольные константы без теоретического обоснования:

| | v1 (three-aspects) | v2 (single-node) |
|---|---|---|
| Состояние на узел | h_v + h_c | один h |
| Матриц на слой | W_cw + W_ccw | W |
| Выход | 0.5·h_v + 0.3·h_c + 0.2·pos (магические коэффициенты) | W_o·h (обучаемый readout) |
| Позиция | добавляется на выходе | добавляется на входе, участвует в циркуляции |
| Residual | отдельный механизм между слоями | встроен в шаг h += Δt·F(h) |
| Backward | два прохода (CCW→CW) с обратной связью h_c→h_v | один поток grad_h по слотам BPTT |

Что дала замена:

- Произвольная смесь 0.5/0.3/0.2 на выходе исчезла — W_o обучается читать состояние сам.
- Backward короче и прозрачнее: один градиентный поток, снимки grad_in на слот.
- Код циркуляции примерно втрое короче.
- На честном бенчмарке v2 решает LongRange: 80.5% token accuracy против 0% у Transformer (см. [Текущее состояние](#текущее-состояние)).

Полный план рефакторинга с обоснованием: plans/12.md.

Оценка для D_MODEL=16:

| NODES | gentr | Transformer (1 слой) | Экономия |
|-------|-------|---------------------|----------|
| 42 (L=3) | 71 KB | 70 KB | 1.0× |
| 123 (L=4) | 139 KB | 204 KB | 1.5× |

| 1,095 (L=6) | ~900 KB | ~16 MB | 18× |
| 3,282 (L=7) | ~2.7 MB | ~140 MB | 52× |

Преимущество растёт квадратично. На размере реального документа (10 000+ токенов) gentr использует на два порядка меньше памяти. Для многослойного Transformer разница ещё больше.

Формулы:
- gentr: M_g ≈ NODES · D · (12 + 2·NUM_LAYERS·D)
- Transformer: M_t ≈ SEQ_LEN² + 4·D² + SEQ_LEN·D·6

## Текущее состояние

### Реализовано

- Single-node архитектура: один вектор состояния h на узел (v2, см. выше)
- Фрактальная топология Серпинского (L=4, 123 узла)
- CRT позиционное кодирование (4 модуля: 2, 3, 5, 7), позиция на входе
- Циркуляция: delta = ReLU(W · D⁻¹·lap(h)), h += Δt·delta + γ·input
- Нормировка лапласиана на степень узла: Δt=0.5 из условия Куранта (запас 2.7×, не зависит от L)
- Stacked layers (2 слоя), residual встроен в шаг (h += delta)
- Readout: output = W_o·h (обучаемая проекция)
- Полный BPTT, градиенты проверены finite differences (0.001–0.5%)
- Gradient clipping (1.0), LR warmup 0.01→0.05→0.1 + cosine decay
- Спектральный анализ: λ_max(D⁻¹L) = 1.5 инвариантен к уровню фрактала (test_spectral)

### Результаты бенчмарка (1200 эпох, L=4, честные данные)

Первая версия бенчмарка была сломана: одна последовательность на все эпохи
(memorization) + обучаемые target-эмбеддинги (вырожденное решение). «Loss gap
27–70×» был фикцией. После фикса (новые данные каждую эпоху, замороженные
эмбеддинги, центрированная инициализация [-0.5, 0.5)):

| Задача | T loss | T acc | g loss | g acc | Итог |
|---|---|---|---|---|---|
| Reversal | 0.0832 | 0% | 0.0939 | 0% | обе на уровне mean-predictor |
| Brackets | 0.0297 | 100% | **0.0056** | **100%** | gentr увереннее (loss 5.3× ниже) |
| LongRange | 0.0834 | 0% | **0.0293** | **80.5%** | gentr решил, T коллапсировал в среднее |

- Transformer (1 слой) на Reversal/LongRange выучил «предсказывай среднее»:
  его loss ≈ дисперсии эмбеддингов (0.083), accuracy = 0.
- gentr выучил LongRange (80.5%) — доставку токена через всю последовательность
  локальной диффузией за 50 шагов циркуляции.
- Метрики: token accuracy через nearest-neighbor decode, per-position buckets,
  диагностика коллапса эмбеддингов (var, mean_norm).

Подробности и история диагностики: plans/13.md.

### Тесты

| Тест | Что проверяет | Статус |
|---|---|---|
| `test_backward` | Аналитические градиенты (W, W_o, эмбеддинги) против finite differences, ε-sweep 1e-2..1e-5 | Проходит (0.001–0.5%) |

### Известные ограничения

- Reversal: 0% у обеих архитектур — честный ноль, задача не решена ни тем, ни другим (см. plans/13.md)
- Loss — MSE по эмбеддингам, не softmax cross-entropy; accuracy считается nearest-neighbor декодированием выхода
- Dynamic edges реализованы, но выключены: на L=4 измеримого эффекта не дали (plans/9.md)
- Transformer-бейслайн минимальный (1 слой, 1 голова) — сравнение предварительное

### Ключевой фрагмент кода: ядро циркуляции

Функция `accumulate_delta_triangle` ([src/gentr_circulation.hpp](src/gentr_circulation.hpp)) — один шаг диффузии для одного треугольника.
Математически: `delta[a] += ReLU( W · (D⁻¹ · (ew₀·h[b] + ew₂·h[c] − (ew₀+ew₂)·h[a])) )`.

```cpp
// Нормированный лапласиан: lap[a] = (ew0·h[b] + ew2·h[c] − (ew0+ew2)·h[a]) / deg(a)
inline void accumulate_delta_triangle(
    const MeshBuffers& mesh, const Triangle& tri,
    const float* __restrict h, float* __restrict delta,
    const float* W, int32_t tri_idx)
{
    int32_t a = tri.a, b = tri.b, c = tri.c;
    const float* edge_weights = mesh.edge_weights;
    float ew0 = edge_weights[tri_idx*3+0], ew1 = edge_weights[tri_idx*3+1],
          ew2 = edge_weights[tri_idx*3+2];
    float inv_a = 1.0f / float(mesh.node_deg[a]);   // нормировка на степень
    float inv_b = 1.0f / float(mesh.node_deg[b]);
    float inv_c = 1.0f / float(mesh.node_deg[c]);
    float lap[D_MODEL], proj[D_MODEL];

    // вершина a
    for (int32_t d = 0; d < D_MODEL; ++d)
        lap[d] = inv_a * (ew0 * h[b*D_MODEL+d] + ew2 * h[c*D_MODEL+d]
                         - (ew0 + ew2) * h[a*D_MODEL+d]);
    matvec(W, lap, proj);
    for (int32_t d = 0; d < D_MODEL; ++d)
        delta[a*D_MODEL+d] += relu(proj[d]);

    // вершины b и c — аналогично
    // ...
}
```
